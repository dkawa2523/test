# ガスケミカルエッチングの新規ガス探索とプロセス開発

課題から選ぶ計算・機械学習の開発指針  
ライブラリ選定表・事前学習モデル改訂：2026年10月6日／基本文献調査：2026年10月5日／追加モデル・データセット調査：2026年10月6日

本レポートは、候補ガスの選定、反応機構の説明、工程条件の設計、溝内の均一性改善に対して、何を用意し、何を計算し、どの結果を開発判断に使うかを整理する。主対象は熱的なガスエッチング、プラズマレスALE、中性活性種による化学反応である。材料・ガス・装置条件を確定した後、各章の採用条件と検証項目に沿って構成を決める。

## 1 課題と必要な情報を定める

### 1.1 計算を始める前に決めること

**この章の目的は、欲しい開発判断を、計算可能な問題に変換することである。** 計算仕様には、ガス名と材料名に加えて表面状態と工程条件を記載する。同じガスでも、表面のOH終端、水分、改質層、被覆率、供給履歴によって結果が変わる。

| 必要な情報 | 具体例 | 情報を揃える方法 |
| --- | --- | --- |
| 除去したい材料と残したい材料 | SiO₂とSiNₓ、酸化物と下地、マスク | 少なくとも対象膜と保護膜を対にして仕様化 |
| 反応前の表面 | 結晶面／非晶質、H・OH・F終端、欠陥、改質層 | 複数の表面仮説を置き、結果の幅を計算 |
| 表面へ到達する化学種 | 導入分子、分解生成物、中性ラジカル、共反応物 | 導入ガスと到達種を分け、必要なら気相反応を計算 |
| 工程条件 | 基板温度、分圧、供給順、曝露・パージ・加熱時間 | 探索範囲を先に決めて感度解析 |
| 判定したい量 | 反応機構、nm/s、EPC、選択比、残渣、溝底の除去量 | 最優先の出力と許容誤差を決める |
| 比較できる実験 | 膜厚、QCM、XPS、FTIR、排気分析、断面 | 最初の検証で得る観測量を計画 |

### 1.2 課題を分けると必要な計算が決まる

| 現在の課題 | 必要な入力 | 計算で補う情報 | その結果で決めること |
| --- | --- | --- | --- |
| 新しいガスが効く理由が不明 | 材料・表面・候補分子 | 吸着、結合切断、揮発化、残渣の経路 | 候補を残す／棄却する → 2章 |
| 反応はするが遅い・止まる | 反応経路、温度・分圧、被覆と工程 | 各反応の速度と中間体の蓄積 | 温度・曝露・パージを変更 → 3章 |
| 平面では除去できるが溝底が残る | 表面反応則、形状、入口の供給分布 | 深さ別到達量、反応消費、再放出 | 供給・工程・形状条件を変更 → 4章 |
| 計算回数が多く開発が進まない | 既存DFT・MDと今後の反復量 | エネルギー・力の近似、追加計算点 | MLIP・能動学習へ投資 → 5章 |
| 高価な実験の次条件を決めたい | 条件と観測値、制約、測定誤差 | 性能予測と不確かさ | 次の候補ガス・レシピを選択 → 5章 |

新規ガスの反応機構を調べる場合は2章、既知の反応係数から工程条件を決める場合は3章、位置ごとの除去量を求める場合は4章から始める。

### 1.3 計算ソフトの役割を分け、受け渡す量を決める

計算環境は、構造とジョブを扱う層、エネルギー・力を求める層、反応経路や軌跡を探索する層、速度・形状を求める層から構成する。ライブラリは担当する処理ごとに選ぶ。DFTは電子状態の計算手法、CP2Kはその実行ソフト、ASEは計算の接続・制御を担う。

| 役割 | 代表的なソフト・モデル | 実際に担当する処理 | 利用者が用意するもの |
| --- | --- | --- | --- |
| 構造と処理をつなぐ | ASE | 原子構造の操作、計算器の呼出し、最適化・NEB等の制御 | 外部計算器、計算条件、実行・保存の仕組み |
| エネルギーと力を計算 | CP2K、Quantum ESPRESSO、VASP、ORCA | 指定構造の電子状態、エネルギー、力 | 表面・分子、電荷・スピン、計算精度 |
| 構造・経路を探索 | GRRM、Pynta、PLUMED | 反応候補生成、反応計算の自動化、CVに沿ったサンプリング | 接続する計算器と、各手法固有の探索条件 |
| 原子の運動を進める | LAMMPS、CP2K等 | 力を使った時間積分と温度・境界の制御 | 有効な力計算器、初期状態、入射・熱浴条件 |
| 工程時間と形状を計算 | Cantera、Zacros、ViennaPS、SPARTA等 | 速度論、輸送、形状のうち各実装が扱う部分 | 反応式と係数、幾何形状、境界条件 |
| 計算・実験を効率化 | MACE等のMLIP、BoTorch等 | 力の近似、性能の近似、次候補の選択 | 参照データ、検証集合、目的と制約 |

## 2 候補ガスが材料を除去できるか調べる

### 2.1 この章の計算仕様

| 項目 | 内容 |
| --- | --- |
| 解く課題 | 新規ガスが対象膜を除去する経路と、保護膜・残渣への影響が分からない |
| 判断すること | 次の計算・実験へ進める候補と、その除去仮説 |
| 必要な情報 | 候補分子、対象・保護膜の構造と終端、共反応物、温度・分圧の範囲 |
| 計算すること | 吸着配置、反応中間体、結合切断・交換、揮発性生成物形成、脱離、競合残渣 |
| 得られる結果 | 反応ネットワーク、反応エネルギー、障壁、生成物候補、表面終端依存 |
| 次への使い方 | 候補を絞り、速度計算へ反応式と障壁を渡す。生成物・中間体の測定項目を決める |
| 後段で求める量 | 3章でエッチ速度と必要曝露時間、4章で溝の均一性 |

### 2.2 吸着から除去後の表面までを一巡させる

図C01では、ガスの吸着後に表面結合が変わり、基板元素を含む生成物が形成され、脱離する。新規ガス探索では、この一巡を一つの評価単位にする。強く吸着するだけのガス、表面を改質するだけのガス、非揮発性の塩を残すガスを区別する。


![吸着→表面反応→揮発性生成物の形成→脱離→残存表面。材料を気相へ運び出す経路と、表面に残る競合経路を比較する。](figures/C01.png)

**図C01。** 吸着→表面反応→揮発性生成物の形成→脱離→残存表面。材料を気相へ運び出す経路と、表面に残る競合経路を比較する。


反応後の表面も計算対象に含める。次の分子が反応できるなら連続エッチングになり得る。一定の改質後に反応が止まり、別のガスや加熱で除去が進むならALEの候補となる。ただし自己制御性の判定には、3章の被覆・時間依存も必要である。

### 2.3 反応を評価する計算器と、経路を探す処理を組む

前節の除去サイクルを数値で比較するには、最初に「構造を与えればエネルギーと力が返る環境」を作る。次に、その計算器を使って吸着構造と反応経路を探索する。この順序で選ぶと、計算ソフトを導入しただけで反応機構まで得られるという見積りを避けられる。

#### 周期表面の基準計算：CP2K、Quantum ESPRESSO、VASP

**CP2Kは、表面DFTからAIMD・QM/MMへ同じ環境で展開したい場合の候補である。** 原子座標、セル、周期境界、電荷・スピン、汎関数、基底・擬ポテンシャルなどを与え、最適構造、エネルギー、力、軌跡を得る。非晶質面や共吸着分子を含む局所反応について、静的経路と有限温度の構造を共通の計算基準で調べる構成にしやすい。無償公開であり、導入時には基底とグリッド、SCF、セル・真空層の収束設定は担当者が確立する。予定する静的計算とMDの代表ケースで、必要精度と計算費用を測って選ぶ。[S01](technical_reference.md#s01)

**Quantum ESPRESSOは、平面波・擬ポテンシャルによる周期DFTを中心に据える場合の候補である。** 表面と吸着種の構造に、擬ポテンシャル、カットオフ、k点、電子占有などを設定して、エネルギー・力を求める。周期表面の反応エネルギーや経路を、平面波計算の資産・経験を使って評価したい場合に適する。無償公開である一方、擬ポテンシャルと数値条件の組合せ、並列計算の設定、ガスと固体の参照条件を自ら管理する必要がある。CP2Kとの選択は、担当者の経験、必要機能、同等精度での費用で行う。[S02](technical_reference.md#s02)

**VASPは、既存の契約・入力資産・検証経験を活かせる場合に有力である。** 周期表面の電子状態・構造・力を求める役割を担い、経路計算やAIMDへ展開できる。有償であるため、初期費用だけでなく、社内で既に確立した計算基準と保守体制を含めて比較する。別の無償ソフトへ移行すると、エネルギー基準や計算条件の再検証が必要となる。単に契約費を削減するために複数の計算器を混在させるより、一つの基準計算器へ統一する方が反応比較を管理しやすい場合がある。[S03](technical_reference.md#s03)

三者の出力は、対象膜・保護膜の吸着エネルギー、反応前後の相対エネルギー、力、最適構造として整理する。精度の評価では、数値収束と表面モデルの妥当性を確認する。汎関数、終端、非晶質サイト、被覆率の選択がガス順位を変えるかを調べる。

#### 分子生成物と予備探索：ORCA、xTB、DFTB+

基板元素を含む気相生成物を評価し、表面から気相への除去経路を確定する。**金属錯体や脱離生成物の安定性・反応障壁を分子レベルで精密評価するときはORCAを使う。** 電子状態、振動、相対エネルギーを求める。金属錯体、配位子交換、脱離生成物の分岐などが主対象となる。入力には構造に加えて電荷・スピンと基底を必要とする。小さな分子反応を高精度化したい場合に選び、周期表面を切り出したクラスターに使う場合は境界の影響を検証する。学術利用と企業利用の条件が異なり、企業での開発は有償条件を前提に確認する。[S04](technical_reference.md#s04)

**xTBは、配位子の向きや分子の会合など、多数の初期構造を安価に作る段階に置く。** DFTへ投入する候補の前処理を担わせ、採否を左右する障壁・生成物順位を統一したDFTで再評価する。入力作成と構造探索を軽くできる一方、対象の表面化学で誤った経路を優先する可能性があるため、複数の候補をDFTで再評価してから選ぶ。[S05](technical_reference.md#s05)

**DFTB+は、適合するパラメータ集合がある化学系で近似量子計算やMDを増やす候補である。** 採用条件は、ガス・基板・生成物に必要な元素ペア、電荷移動、結合環境を一貫したパラメータ集合で扱えることである。代表反応をDFTと比較し、目的の精度を満たした集合を使用する。新しい化学系では、この適合性の確認から着手する。[S07](technical_reference.md#s07)

#### 構造から障壁を作る：ASE、NEB、Sella

計算器が決まったら、**ASEを構造操作と計算器接続の共通窓口**として使う。ASEは構造の読み書き、最適化、NEBなどをPythonで組むためのライブラリであり、通常は外部計算器からエネルギーと力を受け取る。ガス候補・終端・被覆の条件を同じ処理で回したい内製開発に向く。利用者は計算ジョブの投入、失敗の扱い、結果の保存を整備する。計算器固有の機能はネイティブ入力で実行し、共通データ形式で出力を回収する。[S06](technical_reference.md#s06)

始状態と終状態が分かる反応にはNEBを使う。最適化した両端と原子対応、中間像を用意し、各像の力を基準計算器へ問い合わせて経路を緩和する。TSに近い候補がある場合はSella等の鞍点最適化も比較する。Sellaは、TS近傍の構造から局所的な鞍点を精密化するときに使う。いずれも虚振動とその方向、両側へ進めた構造の接続先を確認する。

**図A02。** 構造最適化→経路探索→TS確認→熱化学→速度係数。各箱の出力を検証して次へ渡す。NEBの横軸は反応経路上の位置を表す。反応時間は障壁から速度係数を求めて評価する。


#### 未知経路の発見・反応群の自動計算・有限温度の探索

生成物や途中の反応を発見したいときは、反応経路探索を行う。**生成物や中間体を発見するときはGRRM/AFIRを使う。** 初期構造、探索領域・条件、エネルギー・勾配計算器を与え、会合や配位子交換などの反応候補を得る。有償であり、外部計算器と計算資源の費用も要る。探索領域を広げるほど候補数と検証量が増えるため、反応中心を限定して始め、得た接続をDFT・TS計算で検証する。[S10](technical_reference.md#s10)

**Pyntaは、定義できる反応群について吸着構造・TS・熱化学の計算を自動化するワークフロー**である。多数の類似反応を同じ基準で処理する場合に、手作業の構造生成とジョブ管理を減らせる。反応定義、原子対応、表面サイト、計算器を入力し、指定した反応群を反復計算する用途に使う。公開コードだが、計算器やジョブ管理を含む導入は重い。金属表面以外、特に非晶質や改質酸化物では、サイト表現と反応生成が目的に合うかを小規模に試す。[S11](technical_reference.md#s11)

静的な経路が温度下の分子運動を表しにくい場合には、AIMDで構造変化を観察し、必要に応じ**PLUMEDをMDへ接続して自由エネルギーのサンプリングを補助**する。PLUMEDは配位数・距離などの集団変数（CV）を座標から計算し、バイアスとその力を基礎MDへ返す。経路が既知ならUmbrella、複数の準安定状態を探索するならmetadynamics/OPESを比較する。MD計算器、CV、拘束・バイアス、履歴の解析は利用者が設定する。導入時はMDエンジンとの対応版とビルドを固定し、小系でバイアスの力と履歴出力を確認する。[S12](technical_reference.md#s12)

### 3.2 障壁・付着確率を、反応表へ変換する

2章の出力は構造とエネルギーである。工程時間を求めるには、それを「温度・分圧・被覆率を与えると反応速度が返る式」に変換する。準安定状態とTSが定義できる熱反応には遷移状態理論、気体の吸着には到達フラックスと付着係数を用いる。脱離、拡散、表面同士の反応も、状態と係数の単位を区別する。

反応表には、反応物・生成物、占有サイト数、速度式、係数、逆反応、標準状態、適用温度・被覆、情報源を記録する。電子エネルギーの差に温度・圧力補正を加え、気相と表面の基準を揃える。単一障壁から推定した係数の不確かさは、後の工程予測に伝播させる。[速度変換と感度](technical_reference.md#section-10)

| 反応表の不足 | 情報を補う処理 | 速度論への渡し方 |
| --- | --- | --- |
| 律速候補の障壁 | DFT＋TS、必要ならPLUMEDによる自由エネルギー | 温度依存の係数と不確かさ |
| 入射後の付着・反射・除去確率 | 検証済み力計算器によるMD統計 | 入射条件・表面状態に依存する確率・収率 |
| 反応を止める終端 | 複数被覆のDFT、表面組成の実験 | 状態と反応の追加、被覆依存の係数 |
| 上流で分解して到達種が変わる | 分子計算と気相速度論 | 表面へ到達する種の組成・フラックス |

上流の分解・会合が重要なら、ORCA等の分子計算で井戸・障壁を評価し、必要に応じRRKM/master equationで圧力依存性を求めて、Cantera等へ気相反応表を渡す。障壁は分子計算、時間発展はCanteraという役割分担で構成する。[気相反応の詳細](technical_reference.md#section-31)

反応表が揃ったら、次にどの解像度で表面状態を持つかを決める。平均被覆率で十分ならMKM、近傍配置が反応を左右するならkMC、厚い改質層を通る移動が重要なら反応拡散を選ぶ。

### 3.3 表面状態をどう持つかで、Cantera・kMC・独自モデルを選ぶ

**反応式と速度係数が揃い、温度・分圧・曝露時間から被覆率や除去速度を求めるときはCanteraを使う。** 気相・表面の生成・消費速度を計算し、時間発展を組む。入力には化学種、相、熱化学データ、素反応、速度係数、表面サイト密度、初期被覆、温度・供給条件を用意する。出力は化学種・被覆率・反応速度などであり、基板を除去する反応の収支を集計してエッチ速度やEPCへ換算する。目的ガスの反応表は、2章の計算結果と実験から整備する。[S17](technical_reference.md#s17)

最初の用途は、平面上での吸着・改質・脱離・失活の競合を解き、パルスや温度によって表面が何に覆われるかを調べることである。MKMは平均被覆で状態を表すため、少数の状態で工程応答を作り、感度を調べやすい。Canteraは無償公開でPythonから利用できるが、反応表の設計と係数の同定が開発の中心となる。温度・被覆・供給波形を揃えた実験に対して、速度と表面組成を同時に比較して採用する。

改質層厚さ、層内濃度、履歴変数が多い場合は、Canteraが返す反応速度を独自の物質収支へ接続するか、ODE/PDEとして実装する。独自実装は状態定義の自由度が高い一方、保存則、剛性の強い反応の時間積分、単位、熱力学的な整合を開発者が担う。反応式と係数をデータとして分離すれば、モデル更新のたびにソルバー全体を書き直さずに済む。

図A07のkMC側は、サイトごとの配置を保持する。隣接した吸着種の反応、被覆による遮蔽、島の形成が速度に効く場合、反応できる組合せ数は平均被覆率と局所配置の両方で決まる。この差を解像する必要があるときにkMCを追加する。

### 3.4 付着・除去確率と稀な反応の時間を、MDで求める

前節の反応表で付着・反応・除去確率が不足する場合や、非晶質面のサイト差を平均化したい場合はMDを用いる。MDには原子を動かすエンジンと力計算器が必要である。AIMDは各ステップの電子状態から力を求めるため高価で、少数の未知反応や構造変化を調べる用途に絞る。多数の試行を行うには、適合する反応力場または5章のMLIPが候補になる。

**有効な力場を用意でき、多数の入射から付着・除去確率や改質深さを求めるときはLAMMPSを使う。** 時間積分、入射・拘束・温度制御、並列実行、軌跡出力を担う。ReaxFFはその中で利用できる反応性ポテンシャルの一つで、パラメータファイル、元素対応、電荷平衡条件などを設定する。力場は対象化学系に適合するものを別途用意する。主要生成物、吸着、解離、脱離を同時に再現するパラメータを選び、必要packageとGPU構成を確認する。[S08](technical_reference.md#s08)

LAMMPS＋ReaxFFは、目的系の適合パラメータがあり、多数の衝突・被覆変化を内製スクリプトで制御する場合に選びやすい。出力軌跡から生成物、基板結合、表面への残留を判定する解析器は別途必要となる。短距離で不自然な分解が起きる、熱浴の位置で収率が変わるなどの問題を、試行数を増やす前に解消する。

**AMSは、商用の統合環境でReaxFF計算の準備・実行・解析を進める候補**である。GUIとサポートを利用したいチームでは、初期の作業負担を減らせる可能性がある。採用時はモジュール費用、利用できる力場、反復ジョブの自動化と結果の取り出し方を確認する。LAMMPSと同じ化学を比較するときも、力場版と計算条件を揃える。同梱力場の採用は、新規ガスの吸着・反応・脱離に対するDFT比較で決める。[S09](technical_reference.md#s09)

| MDから求める量 | 必要な条件付け | 次の計算への渡し方 |
| --- | --- | --- |
| 付着・反射・除去確率 | 種、入射エネルギー・角度、温度、初期表面 | 状態依存の確率と試行数・誤差 |
| 生成物分布 | 結合判定と脱離判定、観測時間 | 反応表の分岐候補と排気測定の対象 |
| 改質深さ・損傷・残渣 | 密度・組成・被覆、熱除去条件 | 層モデル、追加の表面状態 |
| サイトごとの反応差 | 複数の独立表面構造 | 係数の分布、MKMで平均化できる範囲 |

稀な反応の待ち時間を求めるときは、時間加速法を検討する。**LAMMPSのhyper・prd・tad**は、準安定状態、状態内平衡化、バイアス境界、高温から低温への外挿など、それぞれの仮定を満たす過程に使う。hyperはバイアスと時間補正、prdは独立レプリカ、tadは高温イベントと障壁情報を利用する。採用は一定被覆での脱離などに範囲を絞り、補正した脱出統計を確認してから行う。[S13](technical_reference.md#s13)

**始状態・終状態と進行度を定義でき、稀な反応への到達時間や流束を求めるときはWESTPAを使う。** 外部の軌跡計算器を利用し、重み付き軌跡の分割・統合を管理する。初期状態・終状態、進行度、ビン、再投入条件などを与えて、稀な到達や流束を調べる。独自のMD計算器を活かしたい場合にも候補となるが、重みの保存と定常化・相関誤差の評価が必要となる。統計誤差は軌跡の重みと相関を含めて評価する。[S14](technical_reference.md#s14)

大きな領域を扱う補助策は別の判断になる。局所反応と周囲の弾性・分極を分けられるならCP2KのQM/MM、厚い層の集団運動ならLAMMPS等の粗視化、平衡被覆の生成ならGCMCを検討する。QM/MMには領域境界と結合方式、粗視化には写像と有効相互作用、GCMCには温度・化学ポテンシャルと挿入・削除則が必要である。粗視化の反応則は原子計算や実験から与える。GCMCの出力は平衡吸着状態として利用する。[S15](technical_reference.md#s15)、[S16](technical_reference.md#s16)

MD・加速法・粗視化を選ぶ共通の基準は、前節の反応表や層モデルに欠けている量を取得できるかである。必要な係数が既に十分なら、全工程をMDで再現する追加投資は省ける。

### 4.3 輸送の近似と、既存ソフトに任せる範囲を決める

3章の表面反応則を受け取ったら、反応する場所まで気体がどう移動するかを決める。判断の入口は、平均自由行程と代表寸法の比であるKnudsen数、分子間衝突の重要性、必要な出力がフィーチャー形状か装置内供給分布か、という三点である。

**検証済みの表面反応則を使って、溝・孔の深さ別除去量と形状変化を求めるときはViennaPSを使う。** 輸送と表面移動を組むプロセスシミュレーション基盤である。幾何形状、材料、入口の粒子分布とプロセスモデルを与え、局所フラックスと表面速度を使って形状を更新する構成を作れる。溝・孔の深さ依存や加工形状を求める用途で、輸送・形状処理の共通部分を再利用したい場合に選ぶ。新規ガスでは、吸着・反射・反応・再放出と表面状態更新を自分の化学モデルとして与える必要がある。[S18](technical_reference.md#s18)

初期導入は公開例の平面・単純溝で、一定の壁反応則を使い、結果の取り出しと形状更新を確認する。その後に、3章の被覆率や改質層を状態変数として接続する。Python配布を利用できる範囲から始め、独自プロセスモデルやGPU実行を必要とする段階で開発環境を拡張する。4.3.0以降のGPLv3を含め採用版の条件を固定する。メッシュ・粒子数を増やす前に、反応則の誤差が予測を支配していないかを確認する。

**希薄気体の分子間衝突と非平衡な速度分布を含めて壁への到達量を求めるときはSPARTAを使う。** 気体を模擬粒子で扱うDSMCソフトである。気体分子の移動と衝突、表面との相互作用を統計的に扱うため、入口の速度分布や気相衝突が到達量を左右する輸送問題に使う。入力には計算領域、境界、ガス種・流入条件、衝突モデル、必要な気相・表面反応を用意し、密度・速度・温度・壁到達量などを得る。無償公開であり、導入時にはセル・時間刻み・模擬粒子数の収束と反応モデルの整備が必要である。[S19](technical_reference.md#s19)

ViennaPSはフィーチャー形状、SPARTAは衝突を伴う希薄気体輸送を求めるときに選ぶ。分子間衝突を省けるフィーチャー形状が主題ならray輸送＋形状更新、衝突を伴う希薄気体分布が主題ならDSMCを選ぶ。DSMCの壁フラックスを別の表面・形状処理へ渡す構成も可能だが、形状変化と輸送の連携は開発項目として計上する。

**Canteraを輸送側で使う場合の役割は、反応速度・熱化学・輸送物性などの供給である。** 反応器の混合・滞留時間を簡略化できるなら反応器モデルから始められる。装置の任意の三次元流れ・熱・壁損失を解く場合には、対応するCFDソルバーと接続する設計が必要となる。三次元装置モデルの構築と、CFD・化学の接続を別の開発工程として見積もる。[S17](technical_reference.md#s17)

### 4.4 何を検証してから形状を信用するか

初めに平面で、表面モデルが3章と同じ除去量を返すことを確認する。次に固定形状で到達量の粒子数・格子依存を確認し、最後に形状を動かす。正味除去フラックスを材料体積へ換算する際、密度変化や塩層の膨張、再堆積を分ける。

結果は最終形状だけでなく、深さごとのフラックス・被覆率・反応消費を並べる。底の除去不足が輸送不足か、到達後の失活かを区別できる出力にする。平面データで調整した係数の評価には、未使用の溝形状・曝露条件を用いる。2026年のHF/NH₃系COR型ALEの会議発表は、改質層・輸送・形状を接続する参考例だが、査読論文や汎用コードの実証と区別する。[R10](technical_reference.md#r10)

## 5 機械学習で計算・探索を効率化する

### 5.1 学習したい対象を最初に分ける

**この章は2〜4章の物理・化学計算とは別の選択肢である。** 機械学習を導入する理由は、必要な計算や実験の反復費用を減らすことに置く。最初に、力の計算、性能予測、次条件の選択のうち、効率化する処理を決める。

| 用途 | 必要なデータ | 学習・処理すること | 出力 | 用途への事前学習 |
| --- | --- | --- | --- | --- |
| 原子計算を速くするMLIP | 原子構造と一貫したDFTのエネルギー・力 | 構造からエネルギー・力への写像 | MD・NEB等に使う力計算器 | 一般事前学習は候補。対象反応に適合済みかは別検証 |
| DFTの追加点を選ぶ能動学習 | 暫定MLIP、探索構造、独立評価集合 | 不確かさ・重要度で構造選別 | 次にDFTを実施する構造 | 目的データから開始できる |
| 性能を近似する代理モデル | ガス・材料・工程条件と速度・EPC等 | 条件から性能への写像 | 性能予測と不確かさ | 目的ラベルが必要。分子の事前学習だけでは不足 |
| 次の試験を選ぶ最適化 | 代理モデル、過去観測、目的と制約 | 改善と不確かさを考慮して候補選択 | 次のガス・レシピ候補 | 目的の観測データから開始できる |

### 5.2 MLIPの開発環境を、予定する使い方から選ぶ

MLIPは原子座標と元素などからエネルギー・力を予測し、2章の構造・経路計算や3章のMDへ返す。ガス候補が少数で必要な経路も限られるなら、DFTを直接使う方が総費用を抑えられる場合がある。同じ化学系で、表面サイト・被覆・温度・衝突条件を繰り返し計算する場合に、モデル開発の価値が生じる。

図B01のデータは、清浄面、改質面、気体分子、生成物、反応途中、短距離接近を含む構造とDFTラベルの対である。参照DFTの条件を揃え、データを反応系列や表面構造で分割する。学習コードを導入する前に、このデータを取得・検証できるかを確認する。


![図B01：一貫したDFTデータ→反応系列等で分割→学習→独立した反応・MD評価→力計算器として利用。モデルの誤差と参照DFTの誤差を分けて評価する。](figures/B01.png)

**図B01。** 一貫したDFTデータ→反応系列等で分割→学習→独立した反応・MD評価→力計算器として利用。モデルの誤差と参照DFTの誤差を分けて評価する。


**目的系のDFTデータを使い、ASEによる構造・経路計算からMLIPを導入するときはMACEを比較の入口にする。** 等変な原子環境表現を使う学習・推論基盤である。構造、エネルギー、力などから専用学習でき、利用可能な重みからの追加学習も候補になる。ASEとの接続を使って少数構造、最適化、NEBから比較を始めたいチームに導入しやすい。PyTorchを使う内製環境との接続を試し、反応障壁、脱離生成物、短距離力を共通テストで確認する。原子数・近傍数・モデル規模で推論費とメモリが変わるため、大規模MDは実際の連携方式で計測する。公開コードの条件と事前学習重みの条件は別である。[S21](technical_reference.md#s21)

**NequIPは、等変グラフモデルによる専用MLIP開発の基盤**として比較する。原子環境の情報を表現するモデルをDFTデータで学習し、エネルギー・力を出す。**Allegroは、局所性を持つ等変ポテンシャルの構成によって大規模並列への展開を狙う候補**である。LAMMPSへ接続した並列MDを主要用途にする場合、両者を同じ精度条件で比較する。学習側だけでなくモデルの配備・コンパイル、LAMMPS連携版、GPUメモリと通信の検証が導入工数に入る。公開モデルがあることと対象エッチングに適合することは別に判定する。[S24](technical_reference.md#s24)

**DeepMD-kitは、エネルギー・力を学習するDeep Potentialの学習からMD配備までを組む基盤**である。構造・ラベルを定義されたデータ形式へ揃え、学習設定と元素対応を固定してモデルを作り、対応するMDインターフェースへ渡す。学習・探索・DFT追加の反復を継続運用したい場合に比較しやすい。PyTorch/JAX等を採用するときは、必要な記述子・学習機能・出力形式・MD配備がそのbackendと版の組合せで使えるかを確認する。採用backendの機能と配備経路を固定し、1構造のエネルギー・力が学習環境とMD環境で一致することから検証する。[S25](technical_reference.md#s25)

**NEPとGPUMDは、対象化学系の学習モデルをGPUのMDへつなぐ構成**として比較する。NEPが原子環境からエネルギー・力を近似し、GPUMDがそのモデルを用いた運動の計算を担う。限定した元素・反応域で多数の軌跡を実行し、学習と推論の総費用を抑えたい場合に候補となる。対象データでの学習と検証が必要であり、反応精度を満たしたモデル同士でGPU計算費を比較する。既存LAMMPS機能に依存する工程では、必要な入射・境界・解析処理をGPUMDで実現できるかも比較する。[S26](technical_reference.md#s26)

**ACE・GAP系は、原子環境の基底・記述子と回帰を用いる専用ポテンシャルの候補**である。少数元素で表現の複雑さとデータ量を系統的に比較したい場合に検討する。実装・利用条件・配備先を確定するため、GAP/QUIP系やACE学習実装など、採用する組合せを特定する。基底や記述子の拡張による精度と計算量、利用権、MDとの接続を個別に評価する。[S27](technical_reference.md#s27)

| 優先する開発条件 | 最初の比較候補 | 利用者側の主な準備 | 比較の決め手 |
| --- | --- | --- | --- |
| Python/PyTorchとASEで小規模から開始 | MACE | 参照データ、反応テスト、重み条件 | 少数DFT追加で必要な反応精度に達するか |
| 等変モデルとLAMMPS並列MD | NequIP・Allegro | データ、配備形式、接続版、並列試験 | 同精度でのメモリ・通信・軌跡費用 |
| 学習・探索・MDを長期運用 | DeepMD-kit | データ変換、backendと配備の固定 | 運用で必要な機能が一貫して利用できるか |
| 特定化学系のGPU軌跡を大量実行 | NEP・GPUMD | 専用データ、境界・入射・解析の確認 | 反応精度と必要軌跡数を含む総費用 |
| 少数元素で表現を系統比較 | ACE・GAP系 | 基底／記述子設計、権利、配備 | データ効率、外挿挙動、表現を増やす費用 |

### 5.3 既存重みを使うか、目的系で学習するかを決める

前節のMACEやNequIP等は学習・推論の実装を指す。事前学習モデルを使う場合には、それとは別に「どのデータとDFT基準を学んだ重みか」を選ぶ必要がある。コードが同じでも、材料用、分子用、表面用の重みで適用領域とエネルギー基準が変わる。

#### 事前学習モデルを、用途と学習データから選ぶ

**本レポートでは、UMAを含む一般事前学習モデルの中から、ガスケミカルエッチング全体に対する最良モデルを特定していない。** 対象膜、ガス、終端、電荷状態が未確定であり、この目的に共通した条件での比較計算も未実施である。採用候補は、学習データと目的処理の近さ、追加学習・配備の実用性から選び、反応ごとの独立テストで決定する。

UMAの強みは多領域を同じ実行基盤で扱えることであり、その利便性と目的エッチングの反応精度を別に評価する。以下ではまず用途ごとの専門表で比較対象を絞り、その後のモデル一覧でデータ・利用条件を確認する。

| 追加学習 | 同じDFT点数・固定評価集合、元領域の評価集合 | 学習曲線、反応誤差、既存性能の変化、総工数 | 一般重み利用・追加学習・新規学習のどれを採るか |
| 工程への接続 | 同じ反応表の構成法と平面実験 | EPC・速度・飽和・残渣、実験の順位 | 原子精度の改善が工程判断に効くか |

評価は二層に分ける。まず各モデルの学習DFTに対する近似誤差を把握する。次に、プロジェクトで採用する共通の基準DFTまたは実験に対して、候補の順位・障壁・工程応答を比較する。後者には参照汎関数の違いも含まれるため、誤差の原因を「学習近似」「DFT基準」「状態の不足」に分けて記録する。

**採用は、反応精度・物理的安定性・利用条件の合格を先に判定し、その合格モデル間で総費用を比較する。** 速度の良さで反応経路の誤りを相殺する採点は避ける。系が未確定の段階では、専門表1から目的に合う2〜3候補を選ぶところまでを開発判断とする。

速度精度から障壁誤差の目安を決める。前因子が同じという近似で、速度の許容倍率を $f$ とすると $|\Delta E_a|\lesssim k_BT\ln f$。たとえば500 Kで2倍以内なら約0.030 eVが目安となる。総エネルギーの平均誤差に加え、採否を左右する**反応ごとのエネルギー差と障壁**を評価する。実際の速度誤差には前因子・被覆・輸送の不確かさも含める。

採用記録では「目的エッチングで事前学習済み」「一般事前学習から転用」「目的系で追加学習」「目的系で新規学習」を区別する。区分は学習データに含まれるガス・表面・反応と、追加学習の履歴から決める。これにより、新しいガス系列が追加されたとき、どのデータと検証を更新すべきかを判断できる。

### 5.4 工程性能を近似して、次のガス・レシピを選ぶ

MLIPが近似するのはエネルギーと力である。新規ガスやレシピの次試験を選ぶには、入力をガス・材料・温度・分圧・曝露など、出力をエッチ速度・EPC・選択性・残渣へ置き換えた代理モデルを作る。同じ「機械学習」でも必要なデータが異なるため、工程性能を求めるモデルには、条件に対応する速度・EPC・残渣等の教師値を用意する。

入力の一行を一つの材料・表面履歴・工程条件に対応させ、観測量、反復、誤差、検出限界を一緒に保存する。実験とDFT・MKMの結果を併用する場合は、情報源と計算条件を区別する。分子表現の事前学習を利用しても、目的の装置・材料における性能ラベルは必要となる。

**過去の条件・性能データから、制約を満たす次の高価な実験や計算を選ぶときはBoTorchを使う。** 確率的な代理モデルと獲得関数を用いる最適化ライブラリである。過去の入力・出力、探索範囲、目的・制約を用意し、予測の良さと不確かさを考慮した候補を得る。PyTorch系の開発へ組み込みやすく、少数の実験を逐次選ぶ場合にはGaussian processを初期候補にする。目的ガスの観測データからモデルを構築し、実験実行、測定結果の取り込み、条件の可否判定を利用者側で接続する。[S29](technical_reference.md#s29)

採用する理由は、試験一回の費用が高く、予測平均だけでなく不確かさを次条件に反映したいことである。一方、測定履歴が乏しく条件の欠測が多い場合は、複雑な獲得関数よりデータ整備と初期実験計画を優先する。木モデルなどの予測基準と同じ未使用データで比較し、最適化ではランダム探索や単純な実験計画と同じ予算で得られる改善を評価する。

### 5.5 機械学習への投資を決める条件

MLIPは「反応を正しく計算する精度」と「繰り返す回数」、代理モデルは「目的ラベルの品質」と「追加試験の費用」が判断軸となる。採用条件は、必要な生成物・障壁・ガス順位の精度を満たし、予定する反復量で総費用を削減できることである。新しいガス系列へ拡張するときは、追加ラベルと再検証の費用を再計上する。

最近の直接関連研究としてHF/非晶質Si₃N₄、F・CF₂/Si・SiO₂の専用MLIPがある。後者はイオン支援条件の実証として参照し、中性熱反応への適用にはその条件の検証を追加する。論文だけでなく重み・学習データ・利用条件の入手性も確認する。[R04](technical_reference.md#r04)、[R09](technical_reference.md#r09)、[最近の実証と限界](technical_reference.md#section-22)

## 6 実装と検証を進める

### 6.1 ソフトの組合せを、一つの開発単位として決める

ここまでの選択を、取得する成果物と実装範囲が明確な構成へまとめる。複数の候補ソフトを同時に導入する前に、一つの経路で「入力→計算→検証→次段階への出力」を通す。下表の構成は採用の初期案であり、既存の社内資産と担当者の経験がある場合は置き換える。

| 開発単位 | 初期構成と役割 | 自ら実装・準備するもの | 最初の受入成果物 |
| --- | --- | --- | --- |
| 未知ガスの反応評価 | ASEで構造・経路を制御、CP2K/QE/VASPの一つで力を計算 | 表面・分子、基準計算、TS接続、計算失敗と保存の処理 | 対象・保護膜の検証済み経路と候補評価票 |
| 平面工程の時間応答 | Canteraで反応速度・被覆を扱い、工程波形と除去収支を接続 | 機構・係数・標準状態、供給切替、EPC換算 | 速度・飽和・組成・生成物の比較 |
| 微細形状の予測 | ViennaPS等で輸送・形状、前段の表面則で壁反応 | 状態依存の反応・再放出、密度換算、適用境界 | 深さ別フラックスと除去量、未使用形状での誤差 |
| 原子計算の大量反復 | MACE等で力を近似、ASE/LAMMPS等で実行 | DFTデータ、独立反応テスト、モデル配備、外挿管理 | 必要精度と軌跡費用を満たすモデル |
| 高価な試験の逐次選択 | 代理モデルとBoTorchで候補提案 | 条件・観測データ、実行可能制約、試験と結果回収 | 同じ予算での改善と確認試験 |

新規ガスをゼロから開発する場合、まず一つのガス・一つの表面で反応経路を作り、平面の物質収支へ渡す。次に保護膜、競合反応、終端・被覆、工程波形を増やす。生成物の探索が不足した時点でGRRM等、局所相関が必要な時点でkMC、反復量が大きい時点でMLIPを追加する。こうすると、追加ソフトの価値を「不足していた情報が得られたか」で判定できる。

**例：HF系に新しい添加分子を導入する場合。** 周期DFTで対象膜と保護膜の共吸着・フッ化・脱離を比べ、必要なら分子計算で生成物候補を調べる。反応が進む候補についてCantera等で被覆・飽和を計算し、温度・曝露・添加量を絞る。平面データで反応則を検証した後にViennaPSへ渡して溝底を評価する。非晶質サイトの統計が係数の不確かさを支配している場合だけ、専用MLIPと多数MDの費用を比較する。

各段階の入力と検証結果を揃えてから、次のソフトへ接続する。次節では、ソフトの機能と利用者側の開発負担を合わせて予算を決める。

### 6.2 費用・導入・保守を含めて最終選定する

比較する費用は、ライセンス、計算資源、入力データ作成、連携実装、科学的検証、運用保守の六つである。無償ソフトでも、未知ガスの反応表や専用MLIPの教師データを作る工数が大きい場合がある。有償環境はGUIやサポート、既存の社内計算資産を活かす価値を含めて評価する。

| 選択場面 | 費用・導入の特徴 | 選定時に実際に試す内容 |
| --- | --- | --- |
| CP2K/QEと既存VASP | 前二者は無償公開、VASPは契約。HPC設定と科学的検証は共通に必要 | 同じ表面・代表反応で精度条件、SCF失敗率、力評価費用 |
| ORCAとxTB/DFTB+ | 精密評価と予備探索の役割が異なる。企業ORCAは有償、近似法はパラメータ等も確認 | 生成物・経路候補の順位がDFT再評価で維持されるか |
| 手動ASE処理とPynta/GRRM | 接続・自動化・未知探索で役割が異なる。Pyntaは公開、GRRMは有償 | 一つの反応群で成功率、検証工数、再実行のしやすさ |
| LAMMPSとAMS | 公開スクリプト基盤と商用統合環境。力場適合性は双方で必要 | 同条件の軌跡、入射・解析の自動化、担当者の作業時間 |
| CanteraとkMC | 平均場と配置依存で必要入力が異なる。Zacrosは商用、SPPARKSは公開 | 必要な局所相関の有無、イベント実装量、反応表の保守 |
| MLIPの自社学習と商用推論 | 自社はデータ・配備・保守、商用は契約範囲・継続費 | 共通反応テスト、追加データ費、版更新時の再検証 |

導入確認は小さな順に行う。外部計算器で1構造のエネルギー・力を取得し、ASE経由と一致させる。MLIPは学習環境とMD環境で同じ力が出ることを確認する。速度論は1反応の収支、形状は平面の除去量を確認する。その後に代表経路、複数条件、並列実行へ拡張する。この順序で、物理モデルの問題と接続処理の問題を切り分けられる。

コード、学習済み重み、データ、力場・擬ポテンシャル、配布物、商用サービスの条件は個別に記録する。MACE本体と重み、UMAの独自条件、ORCAの企業利用、ViennaPSの版ごとの条件などを、それぞれの利用条件と費用を別欄で管理する。非公開の価格は見積りで確認する。[化学計算](technical_reference.md#section-25)、[探索・輸送](technical_reference.md#section-26)、[ML](technical_reference.md#section-27)

選定を終える時点では、ソフト名の一覧に加え、採用する版・モデル、入力を作る担当、検証済みの条件、未実装機能、更新時に再実行するテストを残す。これが次節のデータ成果物と対応していれば、第三者が開発を引き継げる。

### 6.4 検証を通過した段階で計算範囲を広げる

| 段階 | 受入条件 | 追加で実施する作業 |
| --- | --- | --- |
| 表面・電子状態の基準 | 表面仮説と収束条件が明確。設定差が候補順位へ与える影響を把握 | 表面測定または基準計算を追加 |
| 反応機構 | 元素・サイト収支、TS接続、主要競合経路が確認済み | 生成物・反応探索へ戻す |
| 原子モデル | 独立した反応・表面で障壁・生成物・MD安定性を評価 | 用途限定、力場修正、追加学習、DFT継続 |
| 平面工程 | 速度だけでなく飽和・中間体・生成物も説明 | 機構の識別とパラメータの再検討 |

### 6.5 費用と着手判断

費用は、ソフト代、計算資源、データ取得、モデル開発、検証・保守に分ける。DFTは構造数・経路像数・力評価数、MDはステップ数・原子数・独立試行数、輸送は粒子・格子・形状更新数、MLはDFTラベル取得と再検証が主な費用要因となる。具体的な時間は代表ケースを同じ精度で実行して見積もる。[概算式と例](technical_reference.md#section-24)

最初の開発会議では、対象膜と保護膜、候補ガスと到達種、欲しい出力、探索する条件範囲、照合する実験の五点を確定する。その仕様に対し、本章の初期構成を一つ選ぶ。反応機構が不足すれば2章、工程時間が不足すれば3章、空間分布が不足すれば4章、反復費用が支配すれば5章へ進む。
